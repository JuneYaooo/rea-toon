# rea-toon：逆向拆解一切短剧

把一条短剧（或一整部剧的每一集）**逆向成可复查的源码**：每个判断都带证据（镜号、秒数、台词、截图），
用户审过之后锁定。拆解结果有两个用途：给人看（爆款拆解报告：为什么火、套路是什么、怎么拿来用），
给下游用（`rea-toon-remake` 换角色、换画风复刻，只读锁定的拆解）。

原则：**结论附证据，先审后用**。模型认错的地方（谁是谁、谁说的话、哪一镜是看点）都要在审核页上让人一眼能核对。

## 0. 先问清楚

- 单集还是整部剧？整部剧走第 4 步 `series`，每集自动拆，可以断点续跑。
- 要什么：只要爆款拆解报告（编剧/制片用），还是之后要复刻（那 breakdown 要审得更细，并且一定要 lock）。
- 来源：抖音分享文本、视频直链、本地 mp4，或一个放着各集视频的文件夹（按文件名里的数字排序：第2集在第10集前）。

花费：全部只调 VLM（看图/读文本的模型），一集几十次调用；不调图片和视频生成模型。

## 1. 拆一集

```bash
rea-toon analyze work/<名字> --source "<抖音分享文本 | 视频直链 | 本地 mp4>"
```

```bash
rea-toon analyze work/<名字> --source "<抖音分享文本 | 视频直链 | 本地 mp4>"
```
产出 `story.json`（可编辑的剧本源码）和 `story.md`（角色表 + 逐镜表）。OCR 字幕会自动校对一遍形近错字
（百先→首先、目己→自己；原文留在 `ocr` 字段），重烧字幕用的是校对后的文字；旧目录补做：`rea-toon proofread work/<名字>`。
然后自动做两步全剧级的核对（旧目录补做：`rea-toon refine work/<名字>`）：
- **逐句标说话人**（`subtitles[].speaker / on_screen`）：拿整部剧的台词和上下文判断每一句是谁说的、嘴在不在画面里。
  逐镜分析只看静帧、每镜只能填一个说话人，一来一回的对白和画外音就会让**别人的嘴在动**（猫狗版里 28 镜标错）。
  每句还标说法 `mode`：`on` 画内说 / `off` 画外音 / `inner` 内心独白（心声、读心）/ `narration` 旁白。
  只有 `on` 会让嘴动：内心独白是这个人自己的声音，但人就在画面正中嘴也闭着，只用表情演（lipsync 时这段人声也静音）。
  有心声设定的剧审 breakdown 时专门看一遍标成"内心独白"的句子。旧目录 `rea-toon refine` 补标。
  比台词大好几倍的字（出场人名卡，如"温月"）标成 `title`：没人说它，不驱动任何人的嘴。
- **同一人被拆成两个角色**（乔装、女扮男装、换装戴假发）：代码先找出可疑的一对（人名卡上是 A 的名字、画面里却只有 B；
  两人几乎从不同框），再让 VLM 只比这一对的脸和剧情；确认是同一人就合并，另一身衣服记成 `outfits`，按镜头换衣服。
  猫狗版里结尾穿黑西装的"前男友"其实是姐姐女扮男装，拆开后她被换成了哈士奇，观众认不出是姐姐。
最后做**深度拆解**（`rea_toon/breakdown.py`；改过 story.json 或给旧目录补做：`rea-toon breakdown work/<名字>`），
写进 story.json 并出审核页 `breakdown.html`（同内容 `breakdown.md`）：
- **画风档案** `style_bible`：真人感 AI 短剧 / 2D 动漫 / 3D / 动态漫画，渲染质感、色调、角色设计规则、反复出现的特效包装
  （闪白、震屏、花字、慢动作）。漫画/动漫风的剧，复刻时这些和人物设计细节一样要守住。
- **分场与造型** `scenes`：同一地点、连续时间为一场；每个角色在这一场的造型分四项 wear / hair / face / props
  （服装配饰、发型或假发、脸上的面膜/红酒/伤、手里的道具），场内变化（扯掉假发、被泼红酒）记在 `changes`。
  复刻按镜头取这一场的造型给新角色穿，原角色的头发不带过去（假发除外）：不会再把女装场的裙子穿到客厅戏里。
  道具写清哪只手、什么状态（右手半杯红酒 → 空杯），换手、喝空、递给别人都记进 `changes`。
  每场还有剧情日 `day`（D1 / N1 / D2…）和 `flashback`（回忆）：一个角色在某场没描述造型（只露手、背影）时，
  沿用同一剧情日上一场结尾的造型；同一天里两场的衣服对不上会在 lint 里提醒（是剧情换装还是看错了）。回忆场不和现在的同一天共用造型。
- **戏剧节拍和逐镜看点**：钩子、反转、揭露、高潮、爽点、结尾钩子；每镜 role、priority（must 约一到两成）、
  `function`（这一镜的剧情作用和情绪落点：谁对谁做成了什么、观众此刻什么感觉）、
  `keep`（实现它的 1–3 个表情/动作/道具）、特效、`transition_in`（cut / white_flash / fade…，像素亮度也会核对）。
  复刻时 function 和 keep 写进关键帧和视频提示词（见 rea-toon-remake）。
- **画面文字** `shots[].screen_text`：字幕以外的字，本地 OCR 首/中/尾帧，VLM 分成 scene（招牌、手机屏、账单，关键帧原样保留，
  生成后 OCR 核对，没了或写错就重画）、overlay（花字、人物介绍卡，关键帧不画，拼片时按原位置/时间/颜色重画，字体是通用字体）、
  aigc（"AI生成"标识：关键帧去掉，成片统一按 `aigc_label` 加回，原片有就放原位置）、watermark（水印，去掉）。要改花字内容（换了角色名）就直接改 story.json 里的 text。分不出来的标"待定"，lint 提醒。
- **机位和视线** `shots[].staging`：俯拍/仰拍/过肩、每个人脸朝哪边、看着谁、谁居高位。写进视频提示词
  （"机位仰拍，全程保持"），成片检查顺带核对视线，看错了写进 check.md（不触发重试：关键帧已经定住了朝向）。
- **身体接触** `shots[].contacts`：扇、泼、抓、推、递、拍桌。画面先找出有接触的镜头和大概时间，
  再在非人声轨上找 0.3 秒内的音效起点对齐（`sound: true`）。原音轨不变，生成的动作必须落在这一刻：
  写进提示词，ref_video 模式在这一刻加一张中段关键帧，试跑优先挑接触镜头，自查出 `check_hits.jpg`（原片/复刻 接触前·时·后）。
  一直抓着不放的动作（抓手腕）没有"落点"，不算接触瞬间。
- **定格** `shots[].freeze`：画面完全不动的片段（连续相同帧 ≥0.4s，只动嘴的近乎静止不算）。生成的视频不会停住，拼片时冻帧。
  拆解里 fx 写了慢动作的镜头，视频提示词会要求慢动作。
- **画面动法** `shots[].motion`（本地算，不调模型）：still（一张图停着）、pan（一张图推拉/平移，动态漫画常见）、
  partial（画面基本不动，只有一小块在动：眨眼、头发、嘴）、full（正常动画/实拍）。pan 记下镜头窗口随时间的路径。
  still/pan 的镜头复刻时只改一张关键帧（首尾两帧里视野更大的那张），按原路径在本地推拉成视频，**不调视频模型**；
  `plan` 里显示为"静图推拉 N 镜"，不进试跑。partial 的镜头在视频提示词里要求"只有那一块在动"。
  真人感短剧里人在说话、酒滴下落这种小幅动作也会被认成 partial，不会被当成静图（阈值按猫狗版核过：0.2% 像素）。
  首尾两帧谁也不包含谁的大幅横移，按 full 处理。不想用本地推拉就写 `kenburns: false`。
- **特效、漫符、分格**（和机位同一次调用，存在 `staging` 里）：`effects`（剑气、灵光、法阵……颜色、从谁身上发出）、
  `marks`（汗滴、怒筋、问号、速度线）、`panels`（多宫格的格数）。关键帧和视频提示词都要求保住；
  某个角色换了之后特效要换色，在 cast 里写 `fx_color: 金色`。对话气泡归在画面文字里（`kind: bubble`），关键帧原样保留、生成后 OCR 核对。
- **表情清单** `characters[].expressions`：主角和配角这一集用到的 3–8 种表情（名字、长相、哪些镜头）。
  remake.yaml 写 `expression_sheet: true` 会给每个被换的角色多画一张表情设定图，用到这些表情的关键帧把它当参考图
  （变脸是漫剧最常见的翻车）。默认关：多一次出图，老项目开了会重画相关关键帧。
- **风险标签** `risks`（代码算的）：画外音、一镜多人说话、中途入画、闪白开场、短镜/超长镜、大运镜、群众、
  三人以上同框、乔装、场内换造型、人名卡、手部道具、主角背对、静图推拉、局部动、特效、多宫格、漫符、对话气泡。
  中途入画/闪白开场的镜头自动加中段关键帧。
- **一致性检查** `lint`：台词没有说话人、说话人不在角色表、有主角却没表演拆解、镜头没有看点、角色在某场没造型、
  可疑的同一人没合并……error 不修好不能 lock。

审 `breakdown.html`，和用户一起过一遍：
- 每场的造型对不对（猫狗版就是靠它发现：第 59 镜弟弟已经摘了假发，之前的 frame_notes 却写着戴假发）。
- 看点镜头和 keep 是不是这集真正的笑点、爽点；漏了就补到 `shots[].key`。
- 字幕有没有错字（成片会照着重烧）。
- 角色合并对不对（同一人跨镜头、换了衣服也算一个角色）；群众是否合成了 `crowd`。
- 每个角色的 `shots` 有没有漏背影、远景、后视镜里的脸。认错就直接改 `story.json` 的 `characters[].shots`
  或 `shots[].analysis.in_first / in_last`。

改完后 `rea-toon lock work/<名字>`（有 error 会拒绝；确实要带着问题做用 `--force`）。之后再改 story.json 要重新 lock，
再 `rea-toon report work/<名字>` 刷新报告（报告不进 story.json，不会让锁失效）。


## 2. 爆款拆解报告

`analyze` 最后会自动出 `report.html`（同内容 `report.md`、数据 `report.json`）；改过拆解后 `rea-toon report work/<名字>` 重出，
`--no-vlm` 只出代码量出来的数据。

**代码量的数据**（不调模型，按 breakdown 里每镜的戏剧作用算）：
- 节奏曲线：每段时间的情绪强度（爽点/高潮 5、反转/揭露 4、冲突/钩子 3、必保镜头再加）、切镜数、台词字/秒；节拍落在曲线上。
- 爽点分布：第一个冲突、第一个爽点在几秒；爽点/反转之间的间隔，连续 30 秒以上没有爽点的段落标出来（开头铺垫不算）。
- 开头 3 秒的镜头和台词、有没有结尾钩子。
- 人物：出镜秒数、台词字数和句数、对手戏（同框秒数 + 你来我往的台词次数）。
- 镜头语言：平均镜长、每分钟刀数、景别、运镜、画面动法（静图推拉/局部动），多宫格、特效、漫符、气泡、花字的数量。

**类型**（`rea_toon/genre.py`，按数据判断，不调模型；`story.json` 里写 `"format": "<id>"` 可以手动指定）：
`live_action` 真人短剧、`ai_live` AI 真人感短剧、`anime_2d` 2D 漫剧、`anime_3d` 3D 动画、
`motion_comic` 动态漫画（一半以上时长是静图推拉）、`commentary` 解说类（六成以上台词是旁白）。
每种类型有自己要看的点（解说类看解说词结构和语速，动态漫看一张图撑多久，真人看表演和台词冲突），交给模型解读并写进报告。

**模型解读**（一次调用）：一句话卖点、题材/受众/爽感标签、开头钩子、分段结构、套路（和常规用法哪里不同）、
人设和记忆点、关系和张力、为什么留得住人、短板、**可复用公式**（每一步占全集多少时长、不带这一集的人名）、改编方向。
提示词要求每条判断都落到镜号、秒数或台词上。

给用户看报告时：先说卖点和类型，再说节奏曲线上的空白段和可复用公式；报告基于没审过的拆解时要说明。

## 3. 审定（要复刻时必做）

`rea-toon lock work/<名字>`：审过的拆解就是复刻的合同。只要报告不复刻，可以不 lock，但报告页会标"基于未审版本"。

## 4. 整部剧

```bash
rea-toon series work/<剧名> --title "<剧名>" --source 第1集.mp4 第2集.mp4 …   # 或 --source <放着各集视频的文件夹>
rea-toon series work/<剧名>                                                   # 续跑：没拆完的集接着拆，再重做跨集部分
rea-toon series work/<剧名> --source 第11集.mp4                               # 追加新集
rea-toon series work/<剧名> --only-series                                     # 单集都拆好了，只重做跨集部分
```
目录：`work/<剧名>/series.json`、`series.html/.md`，每集是普通的单集目录 `ep01/ ep02/ …`（各有 breakdown.html、report.html）。
- **逐集拆解**：每集走第 1、2 步，已完成的跳过；某一集失败不影响别的集，重跑同一命令续跑。
- **跨集合并角色**：每集的角色 id 是各自起的（第 1 集 `hero`、第 2 集 `linzhou` 可能是同一个人）。
  每集取主要角色最清楚的一张脸拼成头像表，加上身份、外貌、名字线索交给 VLM 合并，得到整部剧的角色表
  （`characters[].members` 记着各集里的 id，如 `E1:hero`）；每集的 story.json 不改（已锁定的拆解不会失效）。
  合并错了直接改 `series.json` 的 `characters[].members`，并在 `series.json` 顶层加 `"cast_fixed": true`，再 `--only-series`：
  之后按手改的合并走，不再调模型重合并（后来追加的集里的新角色单独列出来，再手动归一次）。
- **跨集解读**（一次调用）：整部剧卖点、主冲突、人物弧光（哪一集转折）、伏笔和回收（**还没收的会标出来**）、
  每集结尾钩子和下一集开头怎么接、付费卡点建议、跨集节奏、分阶段打法、反复使用的套路、复用方向。
- 逐集表里有每集时长、爽点数、第一个爽点、结尾钩子，链接到每集的报告和逐镜审核页。

## 已知局限

- 逐句说话人和角色合并靠 VLM 读剧情：人名卡、台词能说明身份时很准；纯靠长相的乔装可能认不出，`story.md` 角色表要人工看一眼。
- 字幕靠 OCR：没有烧字幕的片子（只有配音）台词会是空的，节奏和人物数据只剩画面部分，报告里的台词密度不可信。
- 情绪强度是按镜头的戏剧作用加权算的，不是观众数据；它说明"这部剧把力气花在哪"，不是完播率。
- 跨集合并用每集一张脸：某一集里只有背影、远景的角色可能合并不上，看 series.html 里"每集出镜对照"。
