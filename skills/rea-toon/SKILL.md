# rea-toon：换角色 / 换画风复刻短剧

思路来自 REA（逆向到可复查的"源码"）和 hypit（源码里每个角色是可替换的组件，只重做受影响的部分）。
图片用 gpt-image-2，视频用 MiniMax H3（自部署 `h3local` 或 AutoDL 托管 `h3`）或 Seedance 2.0。

整条流程分 8 步。前 3 步几乎不花钱，第 4 步花图片钱，第 5 步只花十几分钟 GPU，第 6 步才是全片的 GPU/视频钱。
原则：**先预防，再自动检查，最后人工看**。每一步的产物都要看过再进下一步；"跑完了"不等于"做对了"。

## 1. 拆剧本（VLM，便宜）

```bash
rea-toon analyze work/<名字> --source "<抖音分享文本 | 视频直链 | 本地 mp4>"
```
产出 `story.json`（可编辑的剧本源码）和 `story.md`（角色表 + 逐镜表）。OCR 字幕会自动校对一遍形近错字
（百先→首先、目己→自己；原文留在 `ocr` 字段），重烧字幕用的是校对后的文字；旧目录补做：`rea-toon proofread work/<名字>`。先看 `story.md`：
- 字幕有没有错字（成片会照着重烧）。
- 角色合并对不对（同一人跨镜头算一个角色）；群众是否合成了 `crowd`。
- 每个角色的 `shots` 有没有漏背影、远景、后视镜里的脸。认错就直接改 `story.json` 的 `characters[].shots`
  或 `shots[].analysis.in_first / in_last`。

## 2. 和用户对齐换角范围，写 remake.yaml

`rea-toon init work/<名字> <remake名>` 出模板。**先问清楚换谁**，这是最容易做错的一步：
"把剧换成西游记"通常意思是**主角、配角、群众全换**，不是只换新郎新娘。把角色表念给用户，逐个确认对应关系。
- 每个角色写 `name` + `look`（原创外貌描述，不写真人明星）+ `costume`（`keep` = 穿原角色的衣服，剧情道具如胸花保留；
  只取原描述里的服装配饰句子，不会把原演员的长相带进提示词）。
- 换成动物/非人：`look` 里写明"露出来的手脚都是爪子，画面里不能有人类的皮肤和手"，表情跟原片走（狗默认会吐舌头笑）。
  只拍到手脚的镜头也会换（不会因为"看不清脸"就保留原帧）。参考 `examples/maogou_qunbai/`。
- 群众写成 `crowd` 角色（会画一张群像设定图），宽镜头里成片的人一起换；不写 `crowd`，成片里就会站满原片的现代人。
- 没有被换角色的镜头直接复用原片（零成本、完全保真）；设了 `style` 会重做全部镜头。
- 参考：只换主角 `examples/wukong_wedding/`；全员换 `examples/xiyou_wedding/`、自部署 H3 版 `examples/xiyou_wedding_h3local/`。

## 3. 看计划（不花钱）

`rea-toon plan work/<名字> remake.yaml` → 重做哪些镜头、每镜的视频模式、多少次图片/视频调用，
以及**保持原片样子的角色**（没写进 `cast` 的配角、群众和他们出现的镜头）和**试跑镜头**。
把数字和"哪些人不换"告诉用户，确认后再继续。

## 4. 设定图 + 关键帧，先审再出视频

```bash
rea-toon run work/<名字> remake.yaml --until frames
```
每张换人的关键帧会自动和原帧比一次（位置/大小/朝向、镜头框、表情），不通过带着问题重画一次；
被换角色在原帧里小到看不清五官时直接用原帧。仍要人工看 `cast/*.png`、`frames/*.png`、`review.jpg`：
- 构图、机位、光线（暗场/渐亮不能画成白天）和原帧一致；被换角色的表情动作保留；**群众也换了**。
- 不满意：改 `look` 或 `story.json` 再跑同一命令（按输入 hash 只重做变了的）；强制：`--redo 28 --force frames`。
- 关键帧审过后，后面改提示词又不想重画图：`--keep cast,frames`。

## 5. 试跑代表镜头（十几分钟 GPU）

```bash
rea-toon run work/<名字> remake.yaml --pilot
```
`plan` 自动挑 3 个最容易出问题的镜头：被换角色在说话且镜头平稳的（口型）、宽镜头里群众被换且没人说话的
（原片的人会"长回来"）、边说话边大运镜的（重新构图、口型）。只给这 3 镜出视频，拼片并自查。
看 `check.md`、`check_frames.jpg`、`check_subs.jpg` 和这几镜的成片，有问题先改配置（`look`、`no_motion_ref`、
提示词），再跑全片。**模型的实际行为要在这里验证，不要假设**（比如"给了原声嘴就跟原声走"就不成立）。

## 6. 出全片

`rea-toon run work/<名字> remake.yaml`。每镜的视频模式（`plan` 里能看到）：

| 模式 | 什么时候 | 输入 | 特点 |
|---|---|---|---|
| `ref_video` | `h3local`，2–15s、没有被换角色说话（或大运镜）的镜头 | 原镜头当动作参考（脸和字幕打码）+ 新首尾帧 + 设定图 + 原人声 | 运镜、动作最贴原片；原片的人（换动物时尤其是手脚）可能漏回来 |
| `lipsync` | 被换角色在说话、看得见嘴、镜头基本不动（h3local 也优先） | 新首帧 + 设定图 + 这一镜的原人声 | 口型跟原声（试跑 0.90 vs ref_video 0.57，且快 3 倍）；只收首帧，大运镜不用 |
| `first_last` | 其他镜头，或上面两种跑偏后的退路 | 新首帧 + 新尾帧 + 提示词 | 构图最稳；不收音频，台词靠提示词 |

预防（默认就做）：参考视频里所有人脸和字幕打码；给了音频的两种模式提示词里不写台词原文（只写哪几秒在说话），
否则 H3 会把台词当字幕画进画面。

生成后会自动做三道检查（`_guard_lipsync`），不通过就降级 `ref_video → lipsync → first_last`：
- **构图/亮度跑偏**（音频类工作流会改景别、换背景、中途切镜头）：和原片同一时刻抽 5 帧比。
- **漏换**（`ref_video`）：VLM 拿审过的新首帧对比片子中段的两帧，看原片的人有没有"长回来"（衣着、体型被照抄）。
- **口型同步**：H3 会**自己给台词配音**，嘴跟的是它自己的声音，而成片铺的是原声。代码比较 H3 生成的音轨和原人声的响度曲线：
  相似度 < 0.6 就换种子重试（每种模式最多 3 个），保留最好的；相似度 ≥ 0.5 时记下时差，拼接时把画面平移到原声上。

失败镜头重跑同一命令即可续跑，已完成的不会重复计费。`--shots 3,5` 只表示"这次只处理这几镜"，成片始终是整部片：
拼接时每镜都直接读磁盘上的 `clips/<镜头>.mp4` 和它的 `.meta.json`，不依赖上一次运行的状态。

## 7. 拼成片

`run` 跑完会自动拼（也可 `rea-toon assemble ...` 单独拼）：按原时间线拼回、原音轨（对白+歌曲+音效）原样铺回、
先擦掉 H3 仍可能烧进画面的字幕（兜底：OCR 找画面下部居中的字幕样文字再修补），再按原位置、原时间重烧字幕。
每一段拼完都核对帧数，不对直接报错（短几帧，后面所有镜头都会和原声错位）。
产出 `final.mp4`、`compare.mp4`（左原片右复刻）、`review.jpg`。

## 8. 交付前自查（必做）

`run` 结束会自动跑一遍（也可单独 `rea-toon check work/<名字> remake.yaml`），出 `check.md`、`check_frames.jpg`、`check_subs.jpg`：
- **时间线**：成片帧数和原片一致（差几帧以上画面就会和原声错位）。
- **漏换**：计划重做的镜头在成片里不能还是原片；生成时 VLM 判为"原片的人漏回来"的镜头。
- **口型**：每个对白镜头的同步分数，低于 0.6 的列出来。

然后**人工看**（这几类问题自动检查抓不全，都真实漏到过"成片"里）：
- `check_frames.jpg`：每个重做镜头**中段**的原片 | 复刻。首尾帧对了不代表中间对：参考原镜头生成时，
  原片的人（司仪、吃席的群众）会在片中途"长回来"，VLM 漏判的要人工补。有这种镜头就写进 `no_motion_ref` 重做。
- `check_subs.jpg`：每条字幕只有一层。
- `compare.mp4` 抽几段对白带声音看：嘴是否在台词处张合、表情方向和原片一致。

最后把成本（图片/视频调用、GPU 时长）、降级的镜头、仍对不上口型的镜头如实告诉用户。**没看过成片就不要说"做好了"。**

## 选项

| 字段 | 说明 |
|---|---|
| `video_engine` | `h3local`（自部署 H3 ComfyUI，推荐，见下）、`h3`（autodl.art 托管 API，1–15s 整数秒）或 `seedance`（4–15s，首尾帧） |
| `motion_ref` | 默认开（仅 `h3local`）：2–15s 的镜头走 `ref_video` |
| `no_motion_ref` | 不走动作参考的镜头，如 `"19,21-23"`：原片的人中途"长回来"、或参考原镜头总跑偏的镜头。对白镜头会改走 `lipsync`，其余走 `first_last` |
| `frames` | `first_last`（默认，首尾帧双约束）或 `first` |
| `anchors` | 长镜头中间额外换几张关键帧，一起作为参考图喂给 H3（仅 `ref_video`）：`{3: [4.0]}` = 第 3 镜开头后 4.0s。一镜里有换装、场景变化时，每个状态锁一张 |
| `frame_notes` | 给单张关键帧的要求：`{2: {first: "穿第二套…", a1: "…"}}`。一镜里衣服会变、或某张总画错时用；写了的帧不再要求和首帧服装一致 |
| `lipsync` | 默认开（H3）：被换角色的对白镜头用原人声驱动口型 |
| `image_channel` | gpt-image-2 渠道：`cyber`（Chybenzun）/ `krill` / `juling` / `openai` |
| `shots` | 只复刻这些镜头，其余用原片：`"1,28-30"`（命令行 `--shots` 只是"这次只处理这几镜"） |
| `workers` | 并发；单卡自部署 H3 用 `1` |

## 自部署 H3（`video_engine: h3local`）

服务器按 minimax-h3-autodl 部署（ComfyUI 只监听 127.0.0.1:8188），本地先开隧道：
```bash
ssh -f -N -o ServerAliveInterval=20 -L 18188:127.0.0.1:8188 -p <端口> root@<主机>
```
- 引擎连 `http://127.0.0.1:18188`（`H3_COMFY_URL`），1024×576 / 10 步（`H3_LOCAL_STEPS`），种子 `H3_LOCAL_SEED`，24fps、17n+5 帧。
- 参考视频里所有人脸（含群众）自动打码（YuNet，首次下载 ~230KB 模型到 `~/.cache/rea-toon/`）；不打码 H3 会把原演员的脸带回来。
- 单卡串行，一镜 2–5 分钟；36 镜的片约 2–3 小时 GPU。服务端每个任务后会重启 ComfyUI，引擎会自动等服务、取回结果或重提。
- 隧道断了（会话重启、网络抖动）要重开，再跑同一命令续跑。

## 非剧情类素材（换装卡点、带货、动画短片）和换场景

实测踩过的：
- **长镜头要切开**：rea-video 对溶解/穿门/遮挡转场常切不出镜头，一镜 >15s 就走不了 Ref2VA。
  `rea-toon analyze <work> --cuts 7.7,14.8` 强制切。切点选**画面被完全挡住**（椅子扫过、穿门）或转场最乱的瞬间，拼起来看不出接缝。
- **一镜里换装**：只靠 `anchors` 不够，H3 后半段会跟着参考视频把原片的人连衣服一起"变回来"。在每次遮挡处切成一套衣服一镜，
  再用 `frame_notes` 写清楚每张帧穿哪套。
- **换产品**：产品不会进角色表。`cast` 里写一个 `kind: object` 的条目，`original` 写原产品长什么样，它会自动加到每一镜。
- 画面里的贴字 OCR 可能漏掉：用 `frame_notes` 让关键帧去掉，新文案写进对应镜头的 `subtitles` 由后期重烧。
- **换场景（`style`）**：`style` 里写"原来的 A 换成 B"的总表；关键帧按总表重画，质检知道这些改动是预期的。
  视频提示词不放总表（会把别的镜头的场景画进来），而是用 VLM 看新关键帧把这一镜的动作描述改写一遍（存在 `remakes/<名>/motion/`）；
  构图跑偏检查改为和新关键帧比，不和原片比。
- 原帧里有容易认错的东西（手里的玻璃罐像产品、白色液体像粉末、入画时只看到原来的长发），都要写 `frame_notes`，否则视频中途会"变回"原片。
- 没有对白的 Ref2VA 镜头第一次没过检查会先换种子再试一次，再不行才降级首尾帧：长镜头降级会丢掉整段动作。

## 已知局限

- 首帧只拍到手脚、角色脸在后面才出现的大运镜对白镜头（如商场里从高跟鞋摇到脸）：lipsync 会自己编一张脸，
  ref_video 会把人腿带回来，只有首尾帧能用，口型一般。
- 片中的人名条/角色介绍字（不在底部字幕带）不会重烧。
- H3 没有"按给定音频说话"的输入，口型同步是事后对齐：只能整段平移、换种子，做不到逐字；大运镜的对白镜头
  （音频类模式都会跑偏、只能走首尾帧）通常对不上口型。
- 远处小人、快速运镜里的群众偶尔还是原片的样子。
- 换音色（TTS/克隆）还没做，声音只保留原声。
