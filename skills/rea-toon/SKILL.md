# rea-toon：逆向拆解一切短剧

把一条短剧（或一整部剧的每一集）**逆向成可复查的源码**：每个判断都带证据（镜号、秒数、台词、截图），
用户审过之后可以锁定为审定版。rea-toon 用于学习短剧：给人看（爆款拆解报告、剧本、分镜：为什么火、套路是什么、怎么拿来用），
也给模型读（`VIDEO.md` 拆片包，之后问这部剧的任何问题都从它读起）。

原则：**结论附证据，先审后用**。模型认错的地方（谁是谁、谁说的话、哪一镜是看点）都要在审核页上让人一眼能核对。

第一次用先按 [references/setup.md](references/setup.md) 安装（`pip install -e .`、rea-video、ffmpeg）。本仓库不允许商用（PolyForm Noncommercial 1.0.0），用户要商用时提醒他先找作者授权。

## 交付规矩（不要偏离）

用户要的是 rea-toon 的拆解，交付物的格式由代码定，你只负责把流程跑完：

- **交给用户的只有命令生成的东西**：`index.html`（整部剧是剧目录顶上那个）给人看，`VIDEO.md` / `SERIES.md` 给你读。
  不要自己写 HTML 报告、转写稿、抽帧分析来代替或补充，也不要改生成页面的结构。绕开 rea-toon 做出来的东西不是 rea-toon 的拆解，不要这样交付。
- **命令以退出码 0 结束、最后打印出 `→ …/index.html` 才算拆完**。退出码 3 不是出错，是等你答题（见下一节），答完原样重跑。
  没跑完就照实说拆到了哪一步（第几集、哪个阶段），不要说"完成"。
- **卡住了先停下来告诉用户**，或者照本文写的办法处理：装不上、命令报错、片子是合集、拆不动的长剧，都不是换一套自己做法的理由。
  报错时把错误原文告诉用户（仓库问题请用户到 GitHub 提 issue），不要拿抽样分析顶上。
- 只拆了一部分（比如先 `--first 5`）就说清楚是哪几集，页面上也只有这几集。

## 0. 先问清楚

- 单集还是整部剧？整部剧走第 4 步 `series`，每集自动拆，可以断点续跑。一个文件几十分钟、上百分钟的是合集，按下面「合集」先切开。
- 来源：用户已经准备好的本地视频（mp4），或一个放着各集视频的文件夹（按文件名里的数字排序：第2集在第10集前）。不从链接下载：用户只给了链接，就请他先把视频存到本地。

花费：只有"看图/读文本、返回 JSON"这一种问题，快拆一集约 30 道，给的都是静帧拼图。**短剧拆解比较耗 token**（每集要看几十张拼图），
整部剧先 `--first 5` 拆 5 集给用户看，确认效果和花费都能接受，再去掉 `--first` 续跑。

## 谁来看图作答

- **必须能看图**：你看不了图（只能读文字），就不要作答，也不要凭提示词里的文字猜；告诉用户配一个能看图的接口模型（见下面「接口模型」），再用 `--backend api` 跑。
- **默认是你自己（agent）**：不用配任何模型。命令跑到需要判断的地方会停下（退出码 3），把这一阶段的题一次写进
  `<work>/analysis/agent/<key>.json`（`prompt` 提示词、`images` 图片绝对路径、`answer` 答案该写到哪）。你要做的：
  1. 逐题读 `prompt`，用看图工具把 `images` 里的每一张图都看过（不要只凭提示词里的文字猜）；
  2. 按提示词要求的 JSON 写到 `<key>.answer.json`（只写 JSON）；
  3. 全部答完，**原样重跑同一条命令**：答案进缓存，流程接着走到下一阶段，再停、再答，直到跑完。
  一集十几轮（字幕校对 → 角色表 → 逐镜 5 镜一批 → 说话人 → 说话人复核 → 同一人核对 → 分场 → 每场造型 → 画面文字 → 表情 → 节拍 → 报告 → 台词标点 → 剧本润色），
  一轮一般几十秒；第一次跑要先切镜、分轨、OCR，约 10 分钟，深度拆解第一次也要几分钟（结果会存下来，之后不再重算）。
  **命令放到后台跑或者把超时调到 15 分钟以上**，不要因为前台超时就以为卡死了，更不要对同一个目录再开一个进程。
  同一轮的题互相独立，题多时可以分给几个子 agent 并行答；逐镜那一轮每题 5 张图，认人以角色表为准。
  答案不是合法 JSON 会被挪成 `<key>.bad.txt` 并重新出题。整部剧（`series`）是一集一集停，前一集答完才出后一集的题。
- **接口模型**：用户专门给 rea-toon 配了看图模型（`REA_TOON_VLM_BASE_URL / _API_KEY / _MODEL`），或明确要求（`--backend api`、
  `REA_TOON_BACKEND=api`）时才用，任何兼容 OpenAI 接口、能看图的模型都行；按次计费、可并发，适合一次拆几十集。
  从别的项目 `.env` 借来的密钥（`REA_TOON_VLM_FALLBACK_PREFIXES` 里列的前缀）不会自动启用接口，只在 `--backend api` 时作为备选。

## 产物：三个入口

每个拆解目录顶上只有三样东西（完整目录和读法见 [references/outputs.md](references/outputs.md)）：

- `index.html` **给用户看**：只让用户打开这一个，里面是学习分析 / 剧本 / 分镜拆解，整部剧多一行选集。
- `VIDEO.md` **给你读**：拆片包的入口（和 rea-video 同一个开放格式）。先读它（约 2k token：卖点、戏剧骨架、审核状态、要处理的问题、地图），
  按镜头回答时读 `video/timeline.md`，要某一方面按地图开 `video/x-report.md`（为什么火）、`video/cast.md`、`video/content.md`，
  核实某一镜再开 `video/shots/<镜号>.md` 和帧图。整部剧从根目录的 `SERIES.md` 读起。不要读 `story.json` 全文和 `pages/` 里的 html。
- `story.json` **唯一手改的文件**：认错的角色、说话人、看点都改它，改完 `rea-toon redo pages <目录>` 重出页面和拆片包。

其余在子目录：`pages/`（页面和 PDF）、`video/`（拆片包正文）、`frames/`、`characters/`、`data/`（report.json、字幕轨、重做前的备份）、
`analysis/`（答案缓存、等你作答的题）、`decomp/`（rea-video 的切镜和分轨）。

## 1. 拆一集

```bash
rea-toon analyze work/<名字> --source <本地视频> --title "<这条视频叫什么>"
```
`--title` 不给就用文件名；不是 mp4 的文件（mov / mkv / webm）导入时会转成 mp4。一个目录只放一条视频：同一条视频重跑不会再复制，换别的视频会被拒绝，另开一个目录。

重跑同一条 `analyze` 是安全的：已经做完的步骤跳过，只补没做完的，不会覆盖手改过的 story.json 和锁。
只有换了 `--cuts`、或给快拆过的目录加 `--full` 时才会从头重新感知（原来的 story.json 存在 `data/story.prev.json`）。

默认**快拆**（5 个镜头一次调用，约 30 道题）：切镜、字幕 OCR 和校对 → 角色表和逐镜拆解 → 逐句标说话人、合并乔装换装的同一人 →
深度拆解（画风档案、分场造型、画面文字、机位视线、戏剧节拍、逐镜看点和情绪、信息差）→ 风险标签和一致性检查 → 爆款拆解报告 → 剧本和分镜脚本。
只拆剧快拆就够；`--full` 是逐镜单独调用加逐秒表演（贵约 5 倍）。切不出来的转场用 `--cuts 6.65,9.92` 强制切。

跑完和用户一起过一遍（细节和每个字段的含义见 [references/breakdown.md](references/breakdown.md)）：

- 先看 `VIDEO.md` 的「要处理的问题」：error 不修不能 lock；说话人待确认的句子对着原片听一下。
- 角色合并对不对、每场造型对不对、关键镜（必保）是不是这集真正的笑点爽点、字幕有没有错字。
- 认错了直接改 `story.json`。改了角色表、字幕、说话人（深度拆解的输入）要 `rea-toon redo breakdown`；
  只改看点、造型、画面文字（深度拆解的结果）**不要**重跑，会被模型结果整个覆盖（旧版本在 `data/story.prev.json`）。
- 只重做某一步：`rea-toon redo subtitles | proofread | refine | breakdown | report | pages work/<名字>`。

## 2. 爆款拆解报告

`analyze` 最后自动出，在 `index.html` 的「学习分析」里（页面是 `pages/report.html`，你读 `video/x-report.md`）；
改过拆解后 `rea-toon redo report work/<名字>` 重出，`--no-vlm` 只重算数字、保留上一次的文字解读。报告不写 story.json，不会让锁失效。

给用户讲报告：先说卖点和类型，再说情绪打法（靠什么情绪、多久一次、憋→爽）、节奏曲线上的空白段和可复用公式；
报告基于没审过的拆解时要说明。**情绪节点按逐镜的情绪数，不按戏剧节拍数**。数据怎么算、类型怎么判见 [references/report.md](references/report.md)。

## 3. 审定（可选）

只看报告、剧本、分镜可以不 lock，报告页会标"基于未审版本"，`VIDEO.md` 卡片里 `x-review` 是 `unlocked`。
想把审过的拆解定稿：快拆的目录先 `rea-toon deepen work/<名字>`（补逐秒表演和身体接触；快拆没有这两项，lint 会报 error），审完
`rea-toon lock work/<名字>`（有 error 会拒绝，确实要带着问题定稿用 `--force`）。之后再改 story.json 要重新 lock。

## 4. 整部剧

```bash
rea-toon series work/<剧名> --title "<剧名>" --source 第1集.mp4 第2集.mp4 …   # 或 --source <放着各集视频的文件夹>
rea-toon series work/<剧名>                                                   # 续跑：没拆完的集接着拆，再重做跨集部分
rea-toon series work/<剧名> --source 第11集.mp4                               # 追加新集
rea-toon series work/<剧名> --only-series                                     # 单集都拆好了，只重做跨集部分
```

每集是一个普通的单集目录 `ep01/ ep02/ …`。整部剧和一堆单集的区别在于集与集之间有关联，下面几条规则保证这一点：
- **集号就是片源排序后的位置**（第2集排在第10集前面）。某一集导入失败，集号照样留给它，重跑时再导入，后面的集不会往前挪。
- **按顺序拆，每集都带着前面几集定下的东西**（前几集剧情、已出场角色、认脸参考图、上一集的钩子）。
  拆到某一集失败就**停在那一集**，因为后面每一集都要用它的前情：修好后重跑同一条命令。
  这一集确实拆不了（比如片源坏了），在 `series.json` 里给它加 `"skip": true`，它就不算在这条链里，后面接着拆。
- 每集会记下拆的时候带上了哪几集的前情（story.json 的 `prior.eps`）。缺了某一集前情的集，下次重跑会带着前情重拆
  （原来的存在 `data/story.prev.json`）；已经 lock 的集不自动重拆，只在 `SERIES.md` 的「跨集关联要注意」里提示。
- 已经拆完的集跳过，中断了重跑同一条命令就接着拆。
然后跨集合并角色、定整部剧的类型、做跨集解读（主线、人物弧光、伏笔回收、集间钩子、付费卡点），写进 `series.json`。
给用户看 `work/<剧名>/index.html`；你先读 `work/<剧名>/SERIES.md`（卖点、主冲突、情绪打法、主要角色，和每集一行的地图），
要跨集细节读 `pages/series.md`，某一集读 `epNN/VIDEO.md`。

**几十上百集的长剧**能拆，注意三件事（细节见 references/series.md）：
- 用接口模型（`--backend api`）。一集约 30 道题、十来轮停顿，后一集要等前一集答完，100 集由 agent 逐题作答不现实。
- 先 `--first 5` 拆前五集给用户看，确认角色认得对、花费能接受再放开；前面认错的人会带进后面每一集。
- 中断了重跑同一条命令：拆完的集直接跳过。磁盘按每集约 140MB 估（大头是人声 / 配乐分轨）。
合并错了怎么改、类型判错了怎么改见 [references/series.md](references/series.md)。

## 5. 剧本和分镜脚本

`analyze` 和 `series` 跑完自动出（也可以单独 `rea-toon script <单集目录或整部剧目录>`）：标准短剧格式的剧本
（`pages/script.html / .pdf / .md`）和分镜脚本（`pages/storyboard.html / .pdf`：角色设定 + 逐镜表），角色头像、造型图、配音样本在 `characters/`。
每集两次纯文本模型调用（台词补标点、剧本润色，有缓存）。格式细节见 [references/script.md](references/script.md)。
质量取决于拆解：说话人、角色合并、分场错了，剧本跟着错，先改 story.json。

## 片源

- 只支持已经准备好的本地视频：单个视频文件，或一个放着各集视频的文件夹。
- 不支持链接（平台分享链接、视频直链都不行）：视频由用户自己准备好再交给 rea-toon。

## 合集（一个文件里有好几集）

一集短剧一般 1–10 分钟。超过 20 分钟的文件导入时会被拒绝，因为它多半是合集：当一集拆既没有分集和前情，也出不了整部剧的页面，还要一次处理几千个镜头。
1. 先问用户有没有一集一个的文件，有就用那些文件走 `series`。
2. 只有合集的话，先找每集的起点：片头、"第 N 集"字样、黑场、集尾钩子后的重复片头。把找到的起点列给用户确认，然后切开：
   ```bash
   ffmpeg -ss <起点> -to <终点> -i 合集.mp4 -c:v libx264 -crf 18 -c:a aac epNN.mp4   # 每集一条，重新编码才切得准
   ```
   把切好的文件放进一个文件夹，`rea-toon series work/<剧名> --source <文件夹> --first 5`，先拆前五集给用户看。
3. 确实只是一集很长的片子（比如电影式的长篇），才在 `analyze` 加 `--long`。

## 已知局限

- 逐句说话人和角色合并靠 VLM 读剧情：人名卡、台词能说明身份时很准；纯靠长相的乔装可能认不出，`video/cast.md` 的角色表要人工看一眼。
- 字幕靠 OCR：没有烧字幕的片子（只有配音）台词会是空的，节奏和人物数据只剩画面部分，报告里的台词密度不可信。
- 情绪强度和情绪节点是按拆解里每镜的作用和情绪算的，不是观众数据；它说明"这部剧把力气花在哪"，不是完播率。
  每镜的情绪是模型读画面和台词标的，没有听声音：配乐起落、音效卡点没进节奏分析。
- 跨集合并用每集一张脸：某一集里只有背影、远景的角色可能合并不上，看整部剧页里"每集出镜对照"。
