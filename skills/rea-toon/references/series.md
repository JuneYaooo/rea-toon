# 整部剧：逐集拆、跨集合并、跨集解读

命令在 SKILL.md 第 4 步。

- **逐集拆解**：每集走第 1、2 步，按集号顺序拆，已完成的跳过；某一集失败就停在那一集（后面的集要带着它的前情），
  修好后重跑同一命令续跑（已经导入过的视频不会重复加）；确实拆不了的集在 `series.json` 里加 `"skip": true`。
  集号在第一次看到片源时就定下，导入失败也留着，不会让后面的集往前挪。
  没拆完深度拆解的集不进跨集解读；某集重新拆过，它的报告会跟着重出。
  第 2 集起拆剧本时会带上前几集的剧情和已出场角色（记在该集 story.json 的 `prior`），同一个人沿用同一个 id 和身份，
  不会每集重新猜谁是谁（单拆一集时没有这一步）。同时带一张**认脸参考图**（`analysis/cast_before_epNN.jpg`：每个已出场角色
  第一次出场时的样子，上面写着 id），认角色和逐镜拆解都对着它看脸，换装、乔装、长得像的兄弟不靠衣服猜；
  老角色的身份和名字写法直接沿用前面定下的，不让后面的集重新拼。前一集认错了人要先改好再拆后面的集。
- **跨集合并角色**：带了前情的集大多直接同 id，但模型偶尔还是会给同一个人起新 id（第 1 集 `hero`、第 3 集 `linzhou` 其实是同一个人），所以最后再合并一次。
  每集取主要角色最清楚的一张脸拼成头像表，加上身份、外貌、名字线索交给 VLM 合并，得到整部剧的角色表
  （`characters[].members` 记着各集里的 id，如 `E1:hero`；角色名按字幕里的写法校正同音字）；每集的 story.json 不改（已锁定的拆解不会失效）。
  合并错了直接改 `series.json` 的 `characters[].members`，并在 `series.json` 顶层加 `"cast_fixed": true`，再 `--only-series`：
  之后按手改的合并走，不再调模型重合并（后来追加的集里的新角色单独列出来，再手动归一次）。
- **跨集解读**（一次调用）：整部剧卖点、主冲突、情绪打法（哪几集攒、哪一集放，靠哪个信息差撑了多少集）、
  人物弧光（哪一集转折）、伏笔和回收（**还没收的会标出来**）、
  每集结尾钩子和下一集开头怎么接、付费卡点建议、跨集节奏、点赞和结构的关系、分阶段打法、反复使用的套路、复用方向。
- 逐集表里有每集时长、情绪节点数、第一个节点、点赞、结尾钩子，链接到每集的报告和逐镜审核页。
  点赞列只在片源信息里带了点赞数时才有（本地视频没有这一列）。
  付费卡点是模型的建议，不是平台实际的卡点。

## 长剧（几十上百集）

- **能续跑**：逐集拆，拆完的集重跑时直接跳过（不再读它的数据）；某一集失败会停下，修好或标 `skip` 后接着拆。集目录是 `ep01 … ep99 ep100`，站点和地图按集号排。
- **用接口模型**：agent 作答是一集一集停、每集十来轮，上百集请让用户配 `REA_TOON_VLM_*` 并加 `--backend api`。
  先 `--first 5` 试拆（短剧拆解比较耗 token），看角色表、说话人和花费，再去掉 `--first` 续跑。
- **前情不会越带越长**：每集带最近 3 集的剧情；已出场角色超过 24 个时，只带最近出场的 24 个（认脸参考图也是这 24 个），
  很久没出场的老角色回归时可能被当成新人，跨集合并时再并回来。
- **跨集合并角色**：超过 64 个"某集的某个角色"时，同一个 id 只问模型一次（用它第一次出场那一集的脸），不再把每一集的头像都给模型看；
  去重后还超过 64 个 id 时，只问主角、配角里出镜最多的 64 个，其余的一个 id 算一个人。
  这依赖"带着前情拆的集里，同一个 id 就是同一个人"；合并错了照上面的办法改 `series.json` 并加 `"cast_fixed": true`。
- **还会随集数变大的**：跨集解读是一次调用读全部集的摘要和数据，上百集时提示词有几万 token，逐集的集尾钩子可能写不全；
  剧本和分镜页是全剧一页，上百集时分镜页有几千张缩略图、导出 PDF 要几分钟。这两处还没按长剧拆分。
- **磁盘**：每集约 140MB（其中 `decomp/stems/` 的三条分轨约 80MB），100 集约 14GB。

## 长剧的 token 花在哪、怎么省

拆的时候（每集约 30 次调用，大头是图）：
- **联系表**（每镜一格中间帧，12 格一张）给角色表、分场、戏剧节拍三次调用各看一遍，是一集里最大的一笔图。竖屏剧的格子是竖的，
  同样的像素不再把人脸横向拉宽三倍。
- **逐镜拆解**每 5 镜一次调用。整部剧第 2 集起要带认脸参考图：角色表那一次调用看全部已出场角色（最多 24 个），定下这一集有谁；
  之后的逐镜调用只带这一集出场的人的脸。24 人的参考图约是 5 镜画面的 5 倍大，一集十几次逐镜调用，长剧里这是省得最多的一处。
- 前情只带最近 3 集的剧情和上一集的钩子，不随集数变长。
- 答案按"提示词 + 图片内容"缓存：重跑、续跑、`redo pages`、`redo report --no-vlm` 都不重新问。改提示词措辞会让缓存失效。
- 实测过"跨集重复镜头直接沿用"（上集回顾、片头片尾）：10 集 736 镜里只有 3 镜和上一集重复，没有做。

读的时候（你回答用户问题时）：
- 整部剧只读 `SERIES.md`（几千 token，上百集也是每集一行），按它挑集；一集先读 `VIDEO.md`（约 1.5k），再按地图往下。
- 细节没有丢，只是放在更深一层：时间线一行约 50 token（戏剧作用、画面、台词各一次），"为什么这么拍、必须保住什么、造型、机位"在
  `video/shots/<镜号>.md`（每个约 400 token），只在问到那一镜时打开。不要为了"看全"把一集的镜头文件全读一遍。
