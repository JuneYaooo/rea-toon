# 爆款拆解报告：数据怎么算、模型解读什么

`analyze` 最后会自动出 `pages/report.html`（给模型读的同一份内容在 `video/x-report.md`，数据在 `data/report.json`）；改过拆解后 `rea-toon redo report work/<名字>` 重出，
`--no-vlm` 只重算代码量出来的数据，上一次的文字解读保留（数字变了会在页面上标出"解读写在数据更新之前"）。

**代码量的数据**（不调模型，按 breakdown 里每镜的戏剧作用算）：
- 节奏曲线：每段时间的情绪强度（爽/燃/高潮 5、甜/笑/虐/惊/反转/揭露 4、憋/悬/冲突/钩子 3、必保镜头再加）、切镜数、台词字/秒；情绪节点落在曲线上。
- 情绪节点（`rea_toon/emotion.py`）：**按逐镜数，不按节拍数**。节拍是模型对骨架的概括，一集只有五到八条，按它数出来爆款剧也"第一个爽点在 60 秒以后"；
  节点是连续几镜打同一种情绪（中间切到别人的反应不算断）。第一个节点在几秒（晚于 30 秒会提醒）、节点之间的平均和最长空档
  （上一个节点结束到下一个开始：喜剧里连着半分钟一两镜一个梗，是一个长节点，不是半分钟空白）、多少时长在节点里、
  连续 30 秒以上没有节点的段落（开头铺垫不算；整集没有就整集都算）。业内常说每 15–30 秒一个情绪节点。
  逐镜没有情绪（`key.feel`）的拆解出不了报告，先 `rea-toon redo breakdown`。
- 情绪配比：每种情绪几段、多少秒。憋→爽：每个爽点前憋了多久、等了多久；没有先憋就放的爽点几个；片尾还欠着多少秒的憋（留给下一集）。
- 开头 3 秒的镜头和台词（招牌读进字幕的乱码不算）、有没有结尾钩子。跨切点的台词只算一次。
- 人物：出镜秒数、台词字数和句数、对手戏（同框秒数 + 你来我往的台词次数）。
- 镜头语言：平均镜长、每分钟刀数、景别、运镜、画面动法（静图推拉/局部动），多宫格、特效、漫符、气泡、花字的数量。

**类型**（`rea_toon/genre.py`，按数据判断，不调模型；`story.json` 里写 `"format": "<id>"` 可以手动指定）：
`live_action` 真人短剧、`ai_live` AI 真人感短剧、`anime_2d` 2D 漫剧、`anime_3d` 3D 动画、
`motion_comic` 动态漫画（一半以上时长是静图推拉）、`shadiao` 沙雕漫（画风写着沙雕）、`commentary_static` 静态解说漫 / `commentary` 动态解说漫（六成以上台词是旁白，按画面是不是静图分）。
平台按形态给不同的分成系数（抖音漫剧：仿真人、3D 高于 2D，沙雕漫、解说漫低很多），所以形态要判对。
整部剧只有一个类型：`series` 按各集判断里时长占多数的那个定，写进 `series.json` 的 `format`，各集报告跟着它走
（逐集判断时，一部实拍剧里有两集被判成了 AI 真人感）。判错了在 `series.json` 写 `"format": "<id>", "format_fixed": true`。
每种类型有自己要看的点（解说类看解说词结构和语速，动态漫看一张图撑多久，真人看表演和台词冲突），交给模型解读并写进报告。

**模型解读**（一次调用，带前情、情绪账和信息差）：一句话卖点、题材/受众/爽感标签、开头钩子、
情绪打法（靠哪种情绪留人、憋多久才放、片尾欠着什么）、信息差怎么用的、分段结构、套路（和常规用法哪里不同）、
人设和记忆点、关系和张力、为什么留得住人、短板、**可复用公式**（每一步占全集多少时长、不带这一集的人名）、改编方向。
提示词要求每条判断都落到镜号、秒数或台词上。

给用户看报告时：先说卖点和类型，再说情绪打法（靠什么情绪、多久一次、憋→爽）、节奏曲线上的空白段和可复用公式；
报告基于没审过的拆解时要说明。
