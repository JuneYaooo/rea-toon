# 拆一集：每一步做了什么、怎么审

流程和命令在 SKILL.md；这里是每一步的细节，审拆解、改 story.json 时查。产物在哪见 [outputs.md](outputs.md)。

```bash
rea-toon analyze work/<名字> --source <本地 mp4>
```
默认**快拆**：每个镜头的首/中/尾帧拼成一张图，5 个镜头一次调用（机位、视线、特效漫符一起答），不做逐秒表演和身体接触拆解。
实测（一集 143s、60 镜）：模型调用 212 → 约 30 次，48 分钟 → 9 分钟；角色、说话人、分场和完整版基本一致。
学剧（报告、套路、结构）快拆就够；想看逐秒表演和身体接触，再 `rea-toon deepen work/<名字>` 补这两项。
`--full` 逐镜单独调用，并且一开始就做逐秒表演（贵约 5 倍），只在快拆的结果明显不够用时才用。
产出 `story.json`（可编辑的剧本源码）和拆片包 `VIDEO.md` + `video/`（角色表在 `video/cast.md`，逐镜表在 `video/timeline.md`）。OCR 字幕会自动校对一遍形近错字
（百先→首先、目己→自己；原文留在 `ocr` 字段）；单独重做：`rea-toon redo proofread work/<名字>`。
字幕只认**字幕行**上的字：全片字幕都落在同一高度、同一字号（折成两行的以这一行为中心），衣服上的 logo、招牌、车身电话这些
路过字幕区的字不算台词（日志里会列出被排除的字）。台词里还是混进了这类乱码时：`rea-toon redo subtitles work/<名字>`
（重读字幕并同步进 story.json，已标的说话人和校对结果保留，不调模型；重读前的字幕轨存 `data/subtitles.prev.json`），再 `redo report --no-vlm` 刷新报告。
然后自动做两步全剧级的核对（单独重做：`rea-toon redo refine work/<名字>`）：
- **逐句标说话人**（`subtitles[].speaker / on_screen`）：分两步。先拿整部剧的台词和上下文判断每一句是谁说的（每句只问一次，
  同时给出逐镜看图时看到的说话人）；两种判断不一致的句子再带着那一镜的三帧图裁决一次（`refined.speaker_checks` 记着问了哪些、怎么定的）。
  画内 / 画外不让模型猜，由代码按说话人在这一镜里露不露脸来定。看图用的是这句字幕挂在画面上那一刻的三帧，不是镜头的首中尾帧。
  看了图也定不下来的句子（说话的人背对镜头或在画外、几个人同时张嘴、众人齐声）标 `unsure: true`：逐镜页里标着"说话人待确认"，
  审核区逐条列出，对着原片听一下改掉、删掉 `unsure` 即可。实测 10 集 461 句里约四分之一要看图，最后剩 13 句待确认。
  逐镜分析只看静帧、每镜只能填一个说话人，一来一回的对白和画外音就会让**别人的嘴在动**，所以要这一步。
  逐镜看图时新出现、不在角色表里的人（比如两个店员中的另一个），有台词判给他时会作为龙套补进角色表。
  每句还标说法 `mode`：`on` 画内说 / `off` 画外音 / `inner` 内心独白（心声、读心）/ `narration` 旁白。
  只有 `on` 是嘴在动：内心独白是这个人自己的声音，但人就在画面正中嘴也闭着，只用表情演。
  有心声设定的剧审的时候专门看一遍标成"内心独白"的句子。
  比台词大好几倍的字（出场人名卡，如"温月"）标成 `title`：没人说它。
  讲述者不是剧中角色的旁白（解说类）和系统提示音说话人是 `narrator`。说话人不在这一镜画面里、或只有背影的，一律是 `off`。
  一句台词只越过切点零点几秒（OCR 采样的误差）不算进下一镜。
  已经做过深度拆解的目录跑 `refine`，会顺带重算一致性检查、重出 pages/breakdown.html（不调模型）。
- **同一人被拆成两个角色**（乔装、女扮男装、换装戴假发）：代码先找出可疑的一对（人名卡上是 A 的名字、画面里却只有 B；
  两人几乎从不同框），所有可疑的对一次问完，让 VLM 只比这一对的脸和剧情；确认是同一人就合并，另一身衣服记成 `outfits`，按镜头换衣服。
  不合并的话，一个人会被算成两个角色，戏份、对手戏和人物弧光都会算错。
最后做**深度拆解**（`rea_toon/breakdown/`；改过角色、字幕、说话人后重做：`rea-toon redo breakdown work/<名字>`），
写进 story.json 并出审核页 `pages/breakdown.html`（要处理的问题同时列在 `VIDEO.md`）：
- **画风档案** `style_bible`：真人感 AI 短剧 / 2D 动漫 / 3D / 动态漫画，渲染质感、色调、角色设计规则、反复出现的特效包装
  （闪白、震屏、花字、慢动作）。
- **分场与造型** `scenes`：同一地点、连续时间为一场；每个角色在这一场的造型分四项 wear / hair / face / props
  （服装配饰、发型或假发、脸上的面膜/红酒/伤、手里的道具），场内变化（扯掉假发、被泼红酒）记在 `changes`。
  道具写清哪只手、什么状态（右手半杯红酒 → 空杯），换手、喝空、递给别人都记进 `changes`。
  每场还有剧情日 `day`（D1 / N1 / D2…）和 `flashback`（回忆）：一个角色在某场没描述造型（只露手、背影）时，
  沿用同一剧情日上一场结尾的造型；同一天里两场的衣服对不上会在 lint 里提醒（是剧情换装还是看错了）。回忆场不和现在的同一天共用造型。
- **情绪账**（短剧靠情绪留人，不靠幕结构）：每个节拍和每一镜标 `feel`，观众此刻的情绪，八选一或留空：
  爽（打脸、逆袭、亮身份）、憋（主角被羞辱、误解、压制）、虐、甜、笑、悬、惊、燃。憋和悬是在攒，其余是打到观众的。
  节拍另有 `pays`（这次放掉的是哪一次憋、兑现哪个悬念；前几集留下的写"前情：…"）。
  `breakdown.info_gaps` 记**信息差**：谁知道、谁被蒙在鼓里、这一集揭开没有、怎么拿它做戏（装穷、隐藏身份、误会这类剧的发动机）。
  整部剧里第 2 集起，节拍这一步会带上前情和上一集结尾的钩子，能看出开头是不是在接钩子。
  审的时候看一眼：喜剧的笑点有没有标成"笑"（没标就不算情绪节点），主角受气的戏有没有标"憋"。漏标的直接改 `shots[].key.feel`。
- **戏剧节拍和逐镜看点**：钩子、反转、揭露、高潮、爽点、结尾钩子；每镜 role、priority（must 约一到两成）、
  `function`（这一镜的剧情作用和情绪落点：谁对谁做成了什么、观众此刻什么感觉）、
  `keep`（实现它的 1–3 个表情/动作/道具）、特效、`transition_in`（cut / white_flash / fade…，像素亮度也会核对）。
- **画面文字** `shots[].screen_text`：字幕以外的字，本地 OCR 首/中/尾帧，VLM 分成 scene（招牌、手机屏、账单）、
  overlay（花字、人物介绍卡，记下出现的时间和颜色）、aigc（"AI生成"标识）、watermark（水印）。分不出来的标"待定"，lint 提醒。
- **机位和视线** `shots[].staging`：俯拍/仰拍/过肩、每个人脸朝哪边、看着谁、谁居高位。
- **身体接触** `shots[].contacts`（`deepen` 或 `--full` 才有）：扇、泼、抓、推、递、拍桌。画面先找出有接触的镜头和大概时间，
  再在非人声轨上找 0.3 秒内的音效起点对齐（`sound: true`）：动作落在哪一下音效上。
  一直抓着不放的动作（抓手腕）没有"落点"，不算接触瞬间。
- **定格** `shots[].freeze`：画面完全不动的片段（连续相同帧 ≥0.4s，只动嘴的近乎静止不算）。
- **画面动法** `shots[].motion`（本地算，不调模型）：still（一张图停着）、pan（一张图推拉/平移，动态漫画常见）、
  partial（画面基本不动，只有一小块在动：眨眼、头发、嘴）、full（正常动画/实拍）。pan 记下镜头窗口随时间的路径。
  真人感短剧里人在说话、酒滴下落这种小幅动作也会被认成 partial，不会被当成静图（阈值 0.2% 像素）。
  首尾两帧谁也不包含谁的大幅横移，按 full 处理。动态漫画一张图撑多久、多久换图，就是从这里数的。
- **特效、漫符、分格**（和机位同一次调用，存在 `staging` 里）：`effects`（剑气、灵光、法阵……颜色、从谁身上发出）、
  `marks`（汗滴、怒筋、问号、速度线）、`panels`（多宫格的格数）。对话气泡归在画面文字里（`kind: bubble`）。
- **表情清单** `characters[].expressions`：主角和配角这一集用到的 3–8 种表情（名字、长相、哪些镜头）：几种表情撑起一集。
- **留意标签** `risks`（代码算的）：画外音、一镜多人说话、中途入画、闪白开场、短镜/超长镜、大运镜、群众、
  三人以上同框、乔装、场内换造型、人名卡、手部道具、主角背对、静图推拉、局部动、特效、多宫格、漫符、对话气泡。
- **一致性检查** `lint`：台词没有说话人、说话人不在角色表、镜头没有看点、角色在某场没造型、
  可疑的同一人没合并（模型看图判过不是同一人的不再报）、同一场里两人左右换位（可能越轴，也可能是拆解看错了位置）……
  error 不修好不能 lock。

审 `pages/breakdown.html`，和用户一起过一遍：
- 每场的造型对不对（比如某一镜已经摘了假发，之前的描述却还写着戴假发）。
- 看点镜头和 keep 是不是这集真正的笑点、爽点；漏了就补到 `shots[].key`。
- 字幕有没有错字。
- 角色合并对不对（同一人跨镜头、换了衣服也算一个角色）；群众是否合成了 `crowd`。
- 每个角色的 `shots` 有没有漏背影、远景、后视镜里的脸。认错就直接改 `story.json` 的 `characters[].shots`
  或 `shots[].analysis.in_first / in_last`。

哪些改动要重跑 breakdown：改了角色表、字幕、说话人（这些是深度拆解的输入）就重跑；只改 `shots[].key`、分场造型、画面文字这些深度拆解的结果，**不要**重跑，直接 `rea-toon redo pages`——重跑会用模型结果整个覆盖它们（旧版本会存到 `data/story.prev.json`，可以从那里抄回来）。

审完可以 `rea-toon lock work/<名字>` 定为审定版（有 error 会拒绝；确实要带着问题定稿用 `--force`）。之后再改 story.json 要重新 lock，
再 `rea-toon redo report work/<名字>` 刷新报告（报告不进 story.json，不会让锁失效）。
